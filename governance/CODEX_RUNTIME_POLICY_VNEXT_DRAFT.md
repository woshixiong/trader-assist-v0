# Codex Runtime Policy VNext Draft

Status: DRAFT ONLY

Purpose: consolidate Codex execution guidance without creating a parallel governance source.

## Routing

Use the cheapest capable execution path:

- deterministic/mechanical work -> deterministic tools
- bounded semantic work -> appropriate lightweight model
- large coherent coding -> Codex package
- unresolved architecture/security/authority -> Engineering Control

## Cost control

- Do not spend high-capability reasoning on deterministic state checks.
- Prefer GitHub-native CI/state reads over model polling.
- Keep context task-scoped.
- Use subagents only when separation provides measurable value.
- Avoid recursive delegation.

## Codex lifecycle

Plan-only -> pre-code review -> implementation -> focused validation -> CI -> bounded repair -> final review.

## Model policy

Model and reasoning selection belongs to the active controller/governance route, not copied prompts or user memory.

This document is inactive until referenced by the active manifest.

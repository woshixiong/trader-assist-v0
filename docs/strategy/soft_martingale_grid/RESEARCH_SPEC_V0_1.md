独立机制假设：价格在特定低趋势/可回归的区间状态下，可能出现短期条件均值回归；有限价格阶梯可分批提供流动性并在篮子级反弹后退出；**仓位加倍不是 alpha 来源**。自然失败模式：趋势断裂、波动跳变、相关资产共振、滑点及强平早于均值回归。满足零仓位/固定仓位基线后仍未证明 alpha。

## 1. 概念分离与统一数学

**网格（Grid）**：根据价格偏离在预先确定的距离 `Δ_i` 新增限价/被动或触发后下单；这是**价格/订单布置规则**。**马丁格尔（Martingale progression）**：连续不利变化后增大后续订单量；这是**仓位规则**。两者可独立使用。**双向做市网格、单向亏损摊薄网格、突破跟随金字塔**不能混为一谈。

令每层仓位 `q_i`、整数层 `i=0…N−1`、递增乘数 `m`、每 `k` 层递增：

```text
q_i = q0 * m ^ floor(i / k)
m=1.0             => 等手数固定网格
m=1.1~1.3, k=2~3  => 温和递增：待研究的候选范围（不是最优参数）
m=1.5, k=3        => Ryan Brown 2022 视频 Ranger AUD/CAD 实例（非通用推荐）
m=2.0, k=1        => 经典翻倍对照 / 负向风险基线
Q_N = sum(q_i)    => 总敞口；必须在每一步重新核验硬上限
LONG_BASKET_BREAKEVEN ~= sum(q_i * entry_i) / sum(q_i)
BASKET_NET_PNL = sum(side * q_i * (executable_exit_i - entry_i))
                 - ALL_ENTRY_EXIT_FEES - FUNDING - SLIPPAGE - OTHER_VERIFIED_COSTS
```

上述盈亏价公式只适用于线性计价、同币种/合约单位一致的简化示意。真实 Nautilus/venue 回放必须按合约乘数、保证金币种和币对换算计价。**篮子最坏情形浮亏和所需维持保证金必须单独计算**；不能因为单笔订单已止盈就把未平仓篮子的浮亏漏掉。

经典倍增的前 `N` 层名义总量为 `q0(2^N−1)`，极端风险随层数指数增大；固定手数等间距逆势网格的总仓位线性增长、阶梯级未实现损失可近似二次增长。温和 `m>1` 仍可能导致严重尾部损失，不存在“1.1 倍就安全”的结论。

## 3. 独立量化候选协议（待严格预注册）

```text
REGIME_DETECTION:
  仅使用t时点及以前的价格/成交/波动/盘口证据；
  有明确的趋势/跳变/宏观事件排除机制；
  通过回归半衰期、条件收益符号、ATR/价差、
  MAE-恢复概率、Range/Breakout密度判断候选；
  Hurst/ADF/KPSS只是诊断，单项通过不得视为市场稳定。

INITIAL_ENTRY:
  必须有经过验证的偏离/区间边界/短期回归触发；
  不允许“程序启动马上双向开仓”作为有优势的假设。

GRID_SPACING:
  Δ_i = max(可成交价差及费用的明确下限,
            预注册波动归一距离,
            最低交易单位/盘口限制)
  可比较固定间距、ATR自适应间距；
  ATR窗口/阈值只作为待验证参数，不盲目将网格越密越好。

RISK_BEFORE_ORDER:
  每次新增前核验：
  basket max realized+unrealized loss budget、
  total notional、level cap、margin/liq buffer、
  funding/carry、projected stressed gap loss、
  account/venue state、stale data、liquidity
  任何失败 => 不增加仓位或强制安全处置。

STOP/EXIT:
  单篮子明确价位/净值风险上限；
  全账权益上限是第二道保险，而非替代篮子级硬上限；
  达到净利润目标或可观察的回归失效/时间上限即退出；
  错误或数据失效时不继续加仓、禁止隐式无限 rollover；
  强制退出模型包含跳空、滑点、未成交、强平/ADL。

COOLDOWN:
  完成或止损后预冻结冷却期；
  同一单边状态不立即重建满仓网格。
```

要求对手盘、成交价与下单先后必须因果一致。**被动挂单触价 ≠ 真实成交**；强行情中单边被动成交的逆向选择需建模。篮子层级、独立事件层级报告均要保存。

### 最小对照试验矩阵

| 代号 | 设计 | 用途 |
|---|---|---|
| G0 | 相同信号，单笔入场/固定止损/无网格 | 真正的信号 alpha 基线 |
| G1 | 有限等手数网格 `m=1` | 分离网格增益与额外仓位风险 |
| G2 | 有限温和递增 `m=1.1/1.3`，`k=2/3` | 候选；仅从开发集挑一个可解释版本 |
| G3 | `m=1.5,k=3`，仅作为作者例子的复现 | 测试能否跨品种/成本迁移 |
| G4 | `m=2,k=1`，同样强制层数/权益止损 | 明确的高风险否证对照；研究用途 |

## 4. 合适标的是什么：不是固定资产类别，而是条件市场状态

| 候选 | 市场机制适配 | 初步研究排序（仅研究优先级） |
|---|---|---|
| **AUD/CAD 等非高跳变 FX cross** | 作者案例：流动性可用时部分时期存在相对区间往复；也会发生多年结构性趋势和利差变化 | **先用免费 R1 历史做机制/尾部反证**；不能推断实盘合规或可持续 |
| **GBP/CAD** | 可出现区间与大幅趋势并存，点差/跳变和重要宏观事件须剔除；作者其某配置不用递增 | 固定仓网格对照优先，温和递增单独证明增益 |
| **纳指/标普衍生表达** | 某些盘中区间可回归，但市场开盘、新闻、趋势日/隔夜缺口风险显著 | 只考虑明确盘中 range-regime 的研究候选，**非普遍适合** |
| **Hyperliquid 存储股 RWA：SKHX/MU/SNDK** | 单边趋势、财报、相关半导体风险、会话/报价/指数机制跳变；现有风格只证明快损失截断诉求 | **默认排在网格候选后面**；不做逆势摊平，必须先通过精确 R5 及 P0 |
| **BTC/ETH 永续** | 不间断交易、突发趋势/清算瀑布，虽然有震荡期但尾部风险明显；手续费与资金费可能侵蚀小网格 | regime-only 研究，绝非全天候被动放置 |
| **黄金/白银/原油衍生表达** | 新闻/地缘及流动性时段变化；黄金手续费问题、原油跳空大 | 仅做跨品种机制诊断，不优先进入 Trade OS 候选 |

**具体场所/合约/时间段**需由 MVSF（#170）按实际 Hyperliquid 市场表达逐项 P0，包括交易所手续费、最低下单数量、杠杆、维持保证金、强平、标记价、oracle/basis、交易时段/停牌、资金费、盘口深度及真实止损执行。基础标的历史的“均值回归”不能直接证明 HIP-3 合约具有同等表现。ETF/期货/FX 差价合约及 HIP-3 不是同一执行实体。

### 筛选研究必需数据与统计

- 区间状态中的条件未来回撤/反弹幅度与时间，按连续月份、事件日、盘前/盘中/夜盘、趋势强弱分层。
- 预定义 `N` 层在风险止损之前的复原概率 `P(recover before stop | reached layer N)`，需要至少覆盖极端单边趋势和结构性转折的反证。
- 1/5/15m 和更长区间的 realized volatility、ATR、relative spread、liquidity gaps、funding、mark/index basis、K 线以外同分钟路径/成交先后。
- 使用真实篮子维度，收集**未平仓权益低谷**、最长水下时间、强平前的可用保证金，并审查不同交易篮子的相关损失。
- **不把 BTC、存储股、指数同一天的相关大跌误记为多套独立策略**。多资产分散需要相关性/危机共振验证。

## 5. 硬性风险模型及反证

1. **账户级与篮子级风险相区分**。作者提到的 30% 净值退出，是高回撤设置的示例，绝非本项目安全标准。以当前小资金交易偏好的 `$200`、单次约 `2%` 风险为例，一个独立篮子的总可承受损失约 `$4`；若最小手数、价差/手续费与多层保证金无法满足，结论为 `NOT_TRADABLE_AT_THIS_ACCOUNT_SIZE`，不得调整风险预算强行通过。研究中的百分比均为示意，不代表现行实盘授权或冻结参数。
2. **强制停止不能保证止在预算内**：滑点、缺口、无买盘/卖盘、订单延迟、强平、ADL、停牌与系统宕机均需情景压力测试。
3. 如果使用部分平仓/保本退出，必须把所有过往浮亏、已实现亏损、手续费以及保本后立即复开的再入场损失计入周期经济账。
4. **压力情景**：单边 5/10/20 ATR 运动、连续波动升级、低流动性/点差扩大、相关市场危机、资金费反向、执行部分成交、极端事件无报价、2020/2022 类宏观风险状态及其未来同类外推。
5. 必须反证 **固定网格已足够**、**单笔均值回归更优**、**不交易震荡区间更优**、**策略收益完全由额外风险/杠杆解释**、**费用后负期望**。
6. 如果找不到可承受最大亏损的参数区间，候选应 `REJECTED`，而不是追加“更聪明的 AI 滤镜”去掩盖仓位累积风险。

参考历史研究：[MQL5 2020 网格/马丁数学分析](https://www.mql5.com/en/articles/8390) 与 [2026 学术研究 soft martingale / 网格尾部回撤](https://www.mdpi.com/1999-4893/19/6/442)。这类文献并未证明所列作者策略可在 Hyperliquid 上盈利。

遵守 [#280 V1.2](https://github.com/woshixiong/trader-assist-v0/issues/280) 与 [#85](https://github.com/woshixiong/trader-assist-v0/issues/85)：先免费 R1 市场历史机理探索，必要时 R2 高分辨率反证；后再评估 R4/R5 Hyperliquid native 证据，**R5 不作为日常参数调优矿场**；保留后续 OOS/Forward 封存证据。任何未读取的历史不能当作已覆盖的最坏情况。

**核心评价顺序**：
`AFTER_COST_BASKET_EXPECTANCY -> stressed maximum equity drawdown/tail loss -> liquidity & margin survival -> OOS robustness -> capital efficiency -> portfolio correlation -> frequency`。

不符合风险硬门槛的策略，即使月度收益率或胜率很高也不能成为上线候选。**每个策略版本必须记录止损后是否复开及总净值轨迹**，避免只报告已平仓订单。

## 7. 最小优先级与停机/否决节点

- **Phase E0（现在）**：补充频道高信息量视频及真实亏损期，审查用户所给视频的原文字幕及平台第三方 tracker 原始历史；来源不全时用 `UNKNOWN`。
- **Phase E1**：仅以成熟 Nautilus 历史/回放与账务能力作零资金验证；不自建撮合、OMS、执行引擎。
- **Phase E2**：免费 R1 资产筛选和先验否证，固定网格对照 G1 先走，只有 G1 与原始入场 G0 的风险调整、扣费后结果可行才让温和递增 G2 竞争。
- **Phase E3**：选极少独立候选进行封存 OOS、少量精确 Hyperliquid 条件验证；每个候选保留拒绝依据及试验账本。
- **Phase E4**：Shadow-only，由独立验证评估，再讨论后续任何工程/交易需求。研究文档本身**不会触发**自动 Shadow 或部署。
- **停止条件**：无法实现确定的硬损失上限、破产风险不能有界、OOS 期望不达标、重要尾部情景失效、缺少可靠执行语义、实际可用账户规模不满足最小订单/保证金、或收益仅源于不合理加杠杆；一律 `NO_PROMOTION`。

## 8. 作者声称与可审计证据的分界

Ryan 官方展示的 Powerhouse 高风险挑战账户历史快照为约 `+97.72% TWR / 32.18% 最大权益回撤`；另 Project Night Sky 约 `+458.99% gain / 42.04% 回撤`（截至官网 2026-09-30 快照），说明顺滑收益可能伴随极深风险暴露。注意 **TWR gain 与 absolute gain 不同**，不能把营销账户的复利收益曲线直接当作可比独立策略期望。[官网账户页](https://responsibleforextrading.com/) / [历史账户入口](https://responsibleforextrading.com/stats/)。

AlgoLee 的 `2%–5%/月`、`99% 保本机会`、`90% EA 爆仓` 为视频中主张，**无本文所能获取的可审计订单样本支持其量化精度**。某策略能连续运行多年，不等于未观察到的极端结构变化不可能令长期总收益变负。
